# 1C MCP Bridge

**Подключите AI-ассистента (Claude, Qwen, Kimi, Reasonix, ChatGPT) к 1С:Предприятию и работайте с базой как с источником данных через диалог.**

## Что это

`1c-mcp-bridge` — сервер [Model Context Protocol](https://modelcontextprotocol.io/),
который подключает AI-ассистентов (Claude Desktop, Qwen Desktop, Kimi Desktop,
Reasonix, ChatGPT Desktop) напрямую к одной или нескольким информационным базам
1С через COM-коннектор. AI-ассистент получает пять инструментов
(`execute_query`, `describe_object`, `list_metadata`, `get_object_by_ref`,
`list_databases`) и работает с базой как с обычным источником данных:
формулирует запрос на языке запросов 1С, исполняет, возвращает результат,
считает аналитику.

```
┌──────────────────────────┐   stdio / HTTP   ┌──────────────────┐   COM   ┌──────────────────┐
│ Claude / Qwen / Kimi /   │ ────────────────► │ MCP-сервер (Py)  │ ──────► │ 1С:Предприятие   │
│ Reasonix / ChatGPT       │                   └──────────────────┘         └──────────────────┘
└──────────────────────────┘
```

У моста **два транспорта**:

* **stdio** — для Claude Desktop, Kimi Desktop, Reasonix (прописывается
  установщиком автоматически);
* **streamable-HTTP** на `http://127.0.0.1:8000/mcp/<токен>` — для Qwen Desktop
  и ChatGPT Desktop (песочница MSIX не даёт stdio-процессам работать с COM).
  HTTP-сервер запускается без окна (ярлык **«1C Bridge (HTTP-сервер)»**),
  слушает только локальный адрес, доступ защищён секретным путём-токеном.

## Кому это нужно

* **Бухгалтеру / финансовому аналитику**, который хочет сказать «покажи топ-10
  покупателей за апрель» и получить таблицу.
* **Разработчику 1С**, которому удобно проверить структуру конфигурации без
  захода в Конфигуратор.
* **Команде с несколькими базами** (УТ + БП + ЗУП) — AI-ассистент видит все
  настроенные базы сразу, для каждой можно дать осмысленное описание, и он сам
  выбирает правильную для конкретного вопроса.

## Что умеет

| Среда | Поддержка |
|---|---|
| Платформа 1С:Предприятие | 8.2, 8.3, 8.5 |
| Файловая база (.1CD) | да |
| Клиент-серверная база (1С-сервер) | да |
| Аутентификация Windows (OS-auth) | да |
| Аутентификация средствами 1С | да (пароль шифруется DPAPI) |
| Несколько баз одновременно | да |
| ОС | Windows 10 / 11 / Server 2016+ |

> **Только чтение.** Все операции строго read-only: `execute_query` использует
> объект `Запрос`, который не модифицирует данные; инструменты помечены
> `read_only_hint=True` для совместимых клиентов.

4. Установщик автоматически:
   * **останавливает старый HTTP-сервер** моста (точечно, по путям установки —
     посторонние процессы с тем же именем скрипта не затрагиваются);
   * **сохраняет HTTP-токен** (не меняет его при обновлении — не ломаются
     сохранённые URL в Qwen/ChatGPT/Tunnel);
   * настраивает MCP-клиенты: Claude Desktop (`claude_desktop_config.json`),
     Qwen Desktop (npx-лаунчер), Kimi Desktop (`mcp_config.json`),
     Reasonix (`.mcp.json`), ChatGPT Desktop (`%USERPROFILE%\.codex\config.toml`);
   * если HTTP-сервер работал до обновления — **запускает его заново и
     выполняет настоящий MCP health-check** (5 инструментов + `list_databases`);
     при провале установка сообщает об ошибке, а не «успех».
5. Перезапустите MCP-клиенты: Claude Desktop — правый клик по иконке в трее →
   **Quit**; Qwen/Kimi — закрыть и запустить заново; ChatGPT Desktop — полный
   выход из трея и повторный запуск. В новом чате появится сервер `1c-bridge`.

## Подключение к ChatGPT Desktop

ChatGPT Desktop (OpenAI Codex, MSIX) не может запускать stdio-MCP-серверы с
COM/DPAPI внутри своей песочницы, поэтому мост подключается к нему **по HTTP**
через общий `%USERPROFILE%\.codex\config.toml` (этот файл использует и Codex CLI/IDE).

Установщик настраивает это автоматически (если найден `config.toml`):
в `[mcp_servers.1c-bridge]` записывается

```toml
enabled = true
url = "http://127.0.0.1:8000/mcp/<токен>"
```

Патчер точечный: ваши настройки (`tool_timeout_sec`, `required`,
`enabled_tools`, approval-режимы, подсекции `.tools.*`) сохраняются;
удаляются только несовместимые ключи stdio (`command`/`args`/`cwd`) и старая
подсекция `.env`.

Что нужно сделать вручную:

1. Запустите ярлык **«1C Bridge (HTTP-сервер)»** (или дождитесь автозапуска —
   см. [HTTP-сервер и ярлыки](#http-сервер-и-ярлыки)).
2. В ChatGPT Desktop: **Плагины → MCP → Серверы** — включите `1c-bridge`
   (если он в списке, но выключен).
3. Полностью завершите приложение (трей → Quit) и запустите заново, откройте
   новый чат.
4. Проверьте: `/mcp` → `@1c-bridge покажи список информационных баз`.

Ручная настройка (если `config.toml` ещё не создан):

```powershell
# токен и URL
$token = (Get-Content "$env:ProgramData\1cMcpBridge\.http_token" -Raw).Trim()
"http://127.0.0.1:8000/mcp/$token"
```

```toml
[mcp_servers.1c-bridge]
enabled = true
url = "http://127.0.0.1:8000/mcp/<токен>"
```

### ChatGPT Web и Secure MCP Tunnel

Чат на **chatgpt.com** не может достучаться до `127.0.0.1` — запросы идут через
облако OpenAI, и локальный сервер им недоступен. Для веб-версии нужен удалённый
endpoint (публичный HTTPS или **Secure MCP Tunnel**), который на вашем
компьютере сам устанавливает исходящее HTTPS-соединение с OpenAI и пересылает
MCP-вызовы на локальный `http://127.0.0.1:8000/mcp/<токен>`. Входящий порт в
интернет открывать не нужно; в разделе Плагины при создании MCP-сервера
выбирается тип Tunnel с этим URL. После подключения в веб-чате выполните
**Scan Tools / Refresh**, чтобы приложение увидело инструменты.

## Подключение к Qwen Desktop

Qwen Desktop разрешает только `npx`/`uvx` для stdio MCP-серверов. Установщик
автоматически прописывает Qwen через npx-лаунчер моста
(`command = "npx"`, работает из коробки) — ручная настройка HTTP не нужна.

Если настраиваете Qwen вручную через HTTP — используйте **URL с токеном**:
`/mcp` без токена сервер не обслуживает (404).

1. Запустите ярлык **«1C Bridge (HTTP-сервер)»** из меню Пуск.
2. Узнайте токен и соберите URL:

   ```powershell
   $token = (Get-Content "$env:ProgramData\1cMcpBridge\.http_token" -Raw).Trim()
   "http://127.0.0.1:8000/mcp/$token"
   ```

3. В Qwen Desktop: Настройки → MCP → Добавить:
   - Тип: **StreamableHTTP**
   - URL: полученный на шаге 2 (вида `http://127.0.0.1:8000/mcp/<токен>`)

## Другие клиенты (Claude, Kimi, Reasonix)

| Клиент | Файл конфигурации | Транспорт |
|---|---|---|
| Claude Desktop | `%APPDATA%\Claude\claude_desktop_config.json` | stdio |
| Kimi Desktop | `%APPDATA%\kimi-desktop\mcp_config.json` | stdio |
| Reasonix | `%APPDATA%\reasonix\global-workspace\.mcp.json` | stdio |

Все они настраиваются установщиком автоматически: в конфиг добавляется
`1c-bridge` с командой запуска venv-python и `mcp_server_1c.py`. После
установки достаточно перезапустить клиент.

## HTTP-сервер и ярлыки

В меню «Пуск → 1C MCP Bridge» — четыре служебных ярлыка:

| Ярлык | Что делает |
|---|---|
| **1C Bridge (HTTP-сервер)** | Запускает HTTP-сервер в фоне (без окна); токен и путь к базе читает из `%PROGRAMDATA%\1cMcpBridge` при запуске |
| **Остановить HTTP-сервер** | Останавливает только процесс этой установки и освобождает порт 8000 |
| **Перезапустить HTTP-сервер** | Останавливает, запускает заново и выполняет **настоящий MCP health-check** (5 инструментов + `list_databases`); при провале сообщает `RESTART_FAIL` |
| **Статус HTTP-сервера** | Показывает: слушает ли порт 8000, PID, наличие токена, секцию `1c-bridge` в `~/.codex/config.toml`, хвост журнала |

HTTP-сервер слушает только `127.0.0.1:8000`. Журнал — 
`%PROGRAMDATA%\1cMcpBridge\http-server.log` (ротация 5 МБ × 3): туда пишутся
запуск, ошибки импорта/порта и медленные запросы (SHA-256 запроса, без текста).

**Автозапуск при входе в систему** — двумя способами:

* Планировщик заданий: задача **«1C MCP Bridge HTTP»** (создаётся при
  установке), триггер «при входе пользователя», запуск от имени пользователя
  (пароли DPAPI привязаны к пользователю), `/RL LIMITED`;
* либо ярлык **«1C Bridge (HTTP-сервер)»** в `shell:startup`.

## Несколько баз и заметки для AI

В `%PROGRAMDATA%\1cMcpBridge\databases.json` — список баз. Каждая запись:

```json
{
  "enabled": true,
  "description": "УТ 10.3 — управленческая база",
  "progid": "V83.COMConnector",
  "connection_string": "Srvr=192.168.0.35;Ref=ut10;Usr=\"Кувыкин Д.А.\"",
  "notes": "Основная управленческая база ...",
  "dll_path": "C:\\Program Files\\1cv8\\8.3.27.1859\\bin\\comcntr.dll",
  "credential": { "provider": "dpapi-current-user", "blob": "..." }
}
```

Редактировать список удобнее через **«1C Bridge Manager»** (меню Пуск):
добавление/удаление баз, тест подключения, заметки для AI. Пароль хранится в
поле `credential` (DPAPI, привязан к текущему пользователю Windows) и не
попадает в `connection_string`. Manager **сохраняет** credential при
редактировании базы: пустое поле пароля = «оставить прежний»; новый пароль
заменяет credential; переход на Windows-аутентификацию или смена пользователя
сбрасывают его. После сохранения Manager сам перезапускает HTTP-сервер
(если он запущен), чтобы базы подхватились сразу.

`description` и `notes` передаются ассистенту через `list_databases` — именно
по ним он выбирает, какую базу использовать для вопроса.

## Безопасность

* **HTTP-токен** — случайная строка, хранится в `%PROGRAMDATA%\1cMcpBridge\.http_token`.
  Доступ к MCP-серверу возможен только по секретному пути `/mcp/<токен>`:
  `/mcp` без токена возвращает 404. Токен **не пишется** в журналы, VBS-лаунчер
  читает его из файла при запуске, в логах установки — только маска `/mcp/<token>`.
* **Токен не меняется при переустановке** — сохранённые URL (Qwen, Tunnel,
  сторонние клиенты) продолжают работать. Ротация — вручную: остановить сервер,
  удалить `.http_token`, запустить сервер заново (будет создан новый) и обновить
  URL в клиентах.
* **Пароли баз** — DPAPI-шифрование (текущий пользователь Windows). Пароль не
  хранится в открытом виде ни в конфигах, ни в настройках MCP-клиентов
  (клиентам передаётся только команда запуска сервера).
* **Только чтение**: `execute_query` использует объект `Запрос` 1С — данные не
  модифицируются; инструменты помечены `read_only_hint=True`.
* **Остановка процессов** при переустановке — только для процесса текущей
  установки (по точному пути `mcp_server_1c_http.py` и python из её `.venv`).

## Диагностика проблем

1. **Ярлык «Статус HTTP-сервера»** — порт, токен, секция ChatGPT, хвост журнала.
2. **Журнал** `%PROGRAMDATA%\1cMcpBridge\http-server.log` — если сервер «молча»
   не стартует (занят порт, не найден модуль, битый `databases.json`), причина
   будет там. Файл в **UTF-8** — читайте с явной кодировкой:
   ```powershell
   Get-Content "$env:ProgramData\1cMcpBridge\http-server.log" -Encoding UTF8 -Tail 50
   ```
3. **detect_1c.ps1** (в папке установки) — сводка: платформы 1С, Python,
   настройки MCP-клиентов.
4. **`@1c-bridge` не виден в чате?** Перезапустите клиент полностью (трей →
   Quit), в ChatGPT Desktop проверьте «Плагины → MCP → Серверы» (включён ли
   `1c-bridge`) и выполните Scan Tools/Refresh.
5. **Глубокая проверка COM/метаданных** — единый healthcheck с пробой каждой
   включённой базы (tools/list + list_databases + COM-подключение через
   `list_metadata` с заведомо несуществующим фильтром):
   ```powershell
   $env:ONEC_HTTP_TOKEN = (Get-Content "$env:ProgramData\1cMcpBridge\.http_token" -Raw).Trim()
   & "$env:ProgramFiles\1cMcpBridge\.venv\Scripts\python.exe" "$env:ProgramFiles\1cMcpBridge\healthcheck.py" --com
   ```
   Успех: `HEALTH_COM_OK`, код 0. При ошибке выводится `HEALTH_COM_FAIL: <базы>`
   и код 3. Тот же скрипт без `--com` (или с `--database <ключ>` для одной базы)
   используется установщиком и ярлыком «Перезапустить HTTP-сервер» — проверки
   всегда одинаковые.

## Сборка из исходников

```powershell
git clone https://github.com/dimax27/1c-mcp-bridge.git
cd 1c-mcp-bridge

# тесты и линт (release-gate: эти команды выполняются в CI перед сборкой)
python -m compileall -q src installer
ruff check src installer tests --ignore E501,E722
python -m pytest tests -q

# сборка установщика (Inno Setup 6)
$env:APP_VERSION = "0.5.8"
New-Item -ItemType Directory -Path dist -Force | Out-Null
& "${env:ProgramFiles(x86)}\Inno Setup 6\ISCC.exe" /Qp installer/setup.iss
```

Готовый `.exe` появится в `.\dist\` с именем `1cMcpBridge-Setup-0.5.8.exe`.
Версия запекается в `src/version.py` при сборке (сервер показывает версию
установщика), в репозитории дефолт — последний релиз.

### Тесты

`python -m pytest tests -q` — 50+ тестов: юнит (парсер конфигов, TOML-патчер
Codex, DPAPI-логика Manager), HTTP smoke (реальный сервер: токен-маршрут, 404
без токена, read-only аннотации, healthcheck, занятый порт) и installer-тесты
(остановка только целевого процесса, неразрушающий патч, редактирование
stdout).

## Roadmap

* **v0.5.8** *(текущая)* — починка CI (кодировка вывода PowerShell в тесте,
  невалидный SHA `actions/setup-python` в ci.yml), надёжный lifecycle

  стирается при смене аутентификации, release-gate (тесты + ruff) перед сборкой.
* **v0.5.6** — автозапуск HTTP-сервера при входе (Планировщик заданий), ярлыки
  «Остановить/Перезапустить/Статус HTTP-сервера».
* **v0.5.5** — переименован ярлык «1C Bridge (HTTP-сервер)» (общий для Qwen и
  ChatGPT).
* **v0.5.4** — bootstrap-журнал HTTP-сервера (ошибки запуска/импорта видны в
